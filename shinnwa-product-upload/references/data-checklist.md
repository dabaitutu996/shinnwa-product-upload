# 商品资料核对规则

## 必填与字段映射

允许中文、英文或自定义列名，不要求用户重填模板。先展示实际识别的映射，含义不清的列问用户。表中的空值、`-`、`待定`、`N/A` 不是有效资料。

本业务基准是 2026-09-28 已使用的《独立站上架产品信息20260928.xlsx》表头；下表将规则完整列出，同事电脑不需要持有那份历史文件。除 SKU 可生成以外，这些数据都必须有；列名可以不同，不能仅因没有名为“UPC”的列就认定缺失。逐 SKU 检查缺列、空值和冲突；同一商品共享资料须有明确的表格结构或用户确认，不能把相邻行内容擅自复制到空白行。

| 基准列名 | 必需数据及用途 | 缺失处理 |
| --- | --- | --- |
| 品名 | 资料中的内部／中文品名，用于识别商品与图片；不自动替代英文页面标题 | 请用户补充，不自动翻译生成 |
| SKU | 每个规格的商家编码；已有默认保留 | **可自动生成，无须用户补填**，但须查重并展示确认 |
| Product ID | **该规格的 UPC 条码**；此处不是网站后台商品 ID | 请用户补充真实 UPC，不能生成、猜测或写入 `prod_...` |
| Product ID Type | 商品标识类型；本流程应明确为 `UPC` | 缺失时请用户确认并补充；不能因条码有 12 位就擅自填写 |
| Product Name | 商品页面英文名称／标题，可能含对应颜色 | 请用户补充；需要翻译或调整须明确确认，不能只靠中文品名自行完成 |
| Selling Price | 每个规格的实际销售价格 | 请用户补充，不能从成本／旧商品推测 |
| Description | 完整商品描述 | 请用户补充；不能由 AI 自编卖点填空 |
| Color | 该规格的颜色 | 请用户补充，即使单一颜色也不能静默留空 |
| Size | 规格／尺寸／包装数量；历史表中可为 `1 Set`、`1 PC`，不一定是厘米尺寸 | 请用户明确填写实际含义，不能擅自填“默认规格”或 `1 Set` |

如果另有明确的 `UPC` 列，可承载上述 Product ID 的含义；仍核对标识类型。Product ID Type 为 EAN／GTIN 或其他类型时，不视为已提供 UPC，先说明差异并要求用户提供或澄清 UPC。币种不在旧表九列中，但本次仍须明确；可由表格或用户对本批的明确说明提供，不能默认美元。商品分组、图片对应关系和主图顺序同样需要明确，可以由目录及用户确认提供，不强迫新增表格列。

| 资料 | 核对方式 | 缺失／有疑问时 |
| --- | --- | --- |
| 品名、英文名称、描述 | 分别核对上述必填项及完整最终文本；描述中的材质、尺寸、数量等须有来源 | 缺失先补充，不以自行起名／生成描述代替用户资料 |
| 商品分组／商品键 | 识别同一商品的多个规格，颜色不自动拆成多个商品 | 请用户确认合并或拆分，禁止靠相邻行推断 |
| 每个规格的 SKU | 最终上传值非空且唯一；保留已有大小写和前导零，批内及店铺查重 | 缺失按下述规则生成；已有值重复先查清归属 |
| 售价与币种 | 每个规格都有价格；币种使用接口支持的代码；明确表中金额和接口 `amount` 单位的换算 | 禁止把人民币当美元，或猜测乘／除 100；当前说明无单位时查可靠接口资料或店铺已知价格对照，仍不清楚则询问店铺负责人 |
| Color／Size 等规格 | 两项都必填；选项名、选项值、规格组合唯一且能映射到商品 options | 缺哪项就问哪项；单规格不免填，不自行给默认值 |
| 每个规格的 UPC 与类型 | 完整字符串、`Product ID Type=UPC`、原生 `upc` 字段、校验、归属、重复 | 必填。缺失或不可靠先补齐，不以其他条码字段代替 |
| 图片 | 每件商品至少一张可用图片；归属、主图和完整顺序可确认 | 不随便拿其他商品图片顶替；缺图须补齐或明确排除该商品 |

零价格须特别确认是否免费，负数或无法解析金额不可执行。优惠价／原价／成本价不可混用。价格公式无可靠计算值或含错误时不能取缓存猜价格。

分类、集合、标签、销售渠道、运费模板、库存管理和缺货销售：读取 `list_catalog_options` 与当前工具可支持字段。存在多个选项不能任选；唯一合理选项可作建议放入确认单。接口采用默认值时先核实其真实行为，不能把“我没传”说成“已选择某渠道”。需公开上架时，确认渠道、配送和价格使商品能够被销售。库存数、重量、额外物流长宽高、产地等仅在用户资料／目标配置实际需要时要求，不凭空扩展必填项；**表中 Size 仍是必填，不受此可选规则影响。**现有工具不支持的字段要直说，不能假装已上传。

## SKU 自动生成

- 用户已授权缺少 SKU 时自动生成，不要把补填 SKU 作为阻塞问题。表内已有 SKU 默认使用；如用户要求全部重编，先做旧值到新值对照再确认，不能因此改动既有店铺商品的 SKU。
- 每个可售规格单独生成一个简短编码，例如 `SHN-20261028-001-V01`；日期为首次生成的本次日期，商品序号和规格序号依据已核实分组分配。只使用字母、数字和连字符，不编造材质／品类属性。
- 生成后立即保存“源文件／工作表／行号＋商品键＋UPC → 生成 SKU”的映射，纳入本次确认单。检查批内与可查询店铺记录的重复；发生碰撞才调整候选并再确认。即使生成 SKU 没查到，也要继续按 UPC／商品名识别既有商品，不能靠换 SKU 绕过查重。
- 恢复或重新打开同一批资料时复用已确认 SKU，不因日期、行顺序或进程变化重新生成。SKU 生成只能补编码，不能补 UPC、颜色、Size 或其他必填资料。
- 将生成值与其他上传内容一起请用户确认，不需要单独多问一轮。写回位置提前说明；原 SKU 单元格为空可按确认补入，已有值不覆盖，必要时新增“上传SKU”列保留原值。

## UPC／GTIN 专项

- 本流程标准为完整 12 位 UPC-A 字符串，包含有效校验位；如出现 8 位 UPC-E 或其他表示方式，先询问并核实类型和可靠的验证办法，不能自动补零、展开或当成普通 GTIN-8。其他类型 GTIN 校验通过也不代表已满足本流程 UPC 必填。
- 对完整 12 位 UPC-A，从校验位左侧开始向左，对各位交替乘 3、1；`(10 - (加权和 % 10)) % 10` 应等于末位。算法用于检查，**不用于生成缺失的条码或修正条码**。
- 基准表的 `Product ID` 与 `Product ID Type=UPC` 直接映射规格 `upc`，无需再问用户同一个字段映射问题。用户只提供含义不明的“GTIN”时先要求明确 UPC 资料，不能按工具默认写 `barcode` 或只存 metadata。
- 数值型单元格需核对原始值、显示格式及精度；科学计数法、丢失前导零或疑似四舍五入的数字必须向用户索取完整字符串。不要因为长度差一位就补零。
- 不同 SKU 共用 GTIN 属冲突；同一 SKU 的重复资料也要确认是否重复行。用户解释为同一可售实体时先修正分组／重复行，不能用解释绕过平台唯一性要求。
- 在资料和已有店铺中检查可见的所有条码字段，不能只查待写入字段。已确认是同一既有规格时不再创建。无法全面排除跨商品冲突时说明查重覆盖范围，依赖服务端校验并正确报告冲突，不能宣称全库无重复。
- 既有商品字段空白不意味着允许补录；必须在清单中批准旧值 → 新值。清空属于单独的明确请求，不因表格空单元格调用 `gtin: null`。

## 图片映射

“一个商品一个文件夹”是待验证的组织习惯，不是事实保证。优先使用表中图片路径／商品文件夹列，其次使用完全一致的商品键或 SKU；模糊命中只能提出候选。相对路径以用户资料文件夹为基准，确认实际指向正确文件，不擅自读取外部路径。

检查未匹配的行、孤立图片目录、一个目录多件商品、一个商品多个目录、混入其他颜色或其他商品的图片。逐件识别主图和排序；`main`、`01` 等命名可作建议，仍须在确认单展示，不能按文件系统顺序直接上传。多规格图片关联只有当前接口确实支持时才传；不支持时说明只能放到商品级图库。

检查文件可读、实际内容类型、大小及视觉归属。当前图片工具支持 JPG、PNG、WEBP、GIF，解码后的单文件上限 15 MiB；执行时以最新工具定义为准。HEIC、损坏、过大或空文件先解决；不静默转格式、压缩、裁剪或生成替代图。可确定的同商品重复文件可提出去重建议，展示将保留的图片后确认。
